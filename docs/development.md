# Разработка интерфейса

Сейчас приложение работает на React и Vite. Роли переключаются в интерфейсе, демонстрационные работы заданы в коде, а созданные предметы, практические работы, черновики и отправки сохраняются в `localStorage`. Отправка C++ сохраняет снимок решения. Исполнение и проверка кода относятся к следующим этапам. Правила предметной области описаны в [требованиях](requirements.md), этапы реализации — в [плане](PLAN.md).

## Как вносить изменения

1. Пройдите сценарий в нужной роли. При замечании к внешнему виду откройте экран в браузере и определите, какой компонент, параметр или стиль отвечает за результат.
2. Найдите существующую реализацию в таблице ниже. Если нужен новый элемент, проверьте библиотеки организации Gravity UI и API установленной версии. Для новой зависимости сверьте совместимость с React и UIKit в проекте. [Зависимости проекта](../package.json) · [Библиотеки Gravity UI](https://github.com/orgs/gravity-ui/repositories)
3. Проведите изменение через весь сценарий. Например, у нового поля предмета проверьте начальное значение, редактирование, отмену, сохранение, повторное открытие и отображение у студента. Для старых записей учитывайте отсутствующие поля и прежние форматы.
4. Проверьте изменённый сценарий в браузере и выполните сборку. Для изменений компоновки используйте в том числе ширины 390 и 1280 пикселей. В итогах укажите, что именно проверено. Согласованное изменение продуктового правила внесите в требования, а переиспользуемого приёма разработки — в это руководство.

Для локального запуска нужны Node.js 22 и npm. Установите зависимости командой `npm ci`, запустите Vite через `npm run dev`. Команда `npm run build` проверяет сборку, а `npm run preview` позволяет открыть собранное приложение.

Запустите `npm test` для проверки шаблонов JSON, правил импорта и команды `import:json`. Тест команды использует временную копию хранилища.

## Импорт JSON

Преподавателю доступны «Скачать шаблон JSON» и «Импортировать JSON» в разделах «Предметы», «Практические работы» и «Банк задач и тестов». Импорт через интерфейс добавляет записи в текущем браузере. Шаблоны — [предметы](../public/subjects-template.json), [банк](../public/tasks-template.json), [работы](../public/works-template.json). Первое поле `_comment` описывает формат на английском. Имена файлов произвольны.

В форме работы «Добавить задания из JSON» добавляет элементы массива `activities` в конец черновика. У каждого редактируемого теста или задачи есть собственный импорт одного элемента соответствующего типа. Он заменяет содержимое этого элемента на прежнем месте. Изменения сохраняются при создании работы. Шаблоны: [набор заданий](../public/activities-template.json), [тест](../public/quiz-template.json), [задача](../public/program-template.json).

Из корня проекта можно добавить данные без браузера:

```sh
npm run import:json -- subjects.json tasks.json works.json
```

Команда обрабатывает переданные файлы по порядку и сохраняет весь набор после проверки в [исходные данные приложения](../src/imported-data.json). Vite подхватывает изменения при локальной разработке. Для собранного сайта выполните новую сборку. Эти материалы доступны в профилях приложения по обычным правилам доступа. Правки, сохранённые пользователем в браузере, имеют приоритет для того же ID.

Указывайте уникальные `id` для повторных ссылок. Поле `subject` содержит ID предмета (например, `cpp`), что позволяет различать одноимённые предметы разных лет. В интерфейсе выбранный предмет подставляется для строк без `subject`. В командной строке указывайте его в каждой работе, задаче и теоретическом вопросе. Сначала импортируйте предмет, затем задачи банка и работы, которые ссылаются на эти задачи. При отсутствии ID создаётся новый UUID. Повторный импорт явного ID отклоняется. В примерах даты приведены для 2026/2027; подставляйте учебный год и локальные сроки нужного предмета.

## Компоненты в проекте

| Задача | Что использовать | Пример |
| --- | --- | --- |
| Навигация между разделами | `AsideHeader` и `MobileHeader` из `@gravity-ui/navigation`, профиль через `User` и `Avatar` из UIKit | [WorkspaceNavigation](../src/WorkspaceNavigation.jsx) |
| Создание и настройки предмета, прохождение работы | Общая полноэкранная страница `WorkspacePage`. В форме предмета действия «Отмена» и «Создать» или «Сохранить» остаются доступны при прокрутке. Кнопка в шапке возвращает на экран, откуда открыли работу: «К предмету», «К обзору» или «К работам». Поиск и фильтры этого экрана сохраняются. Экран студента занимает всю ширину. Слева находятся таймер и номера вопросов теста, в центральной колонке — условие и ответы, список заданий справа появляется после завершения попытки теста и при решении задач по программированию. На телефоне при тех же условиях появляется выбор задания над условием. Под карточкой находятся кнопки перехода между вопросами. После завершения теста на их месте появляются кнопки перехода между заданиями с учётом порядка доступа | [WorkspacePage](../src/WorkspacePage.jsx) |
| Создание и редактирование практической работы | Кнопки в предмете и в общем списке работ открывают полноэкранную форму с действиями «Отмена» и «Создать». Кнопка «Редактировать работу» в открытой работе использует ту же форму с текущими данными и действием «Сохранить». Форма удерживает Web Lock по ID работы. Подтверждение начала использует ту же блокировку. В браузерном прототипе это связывает вкладки одного профиля и origin. Упорядоченный список объединяет тесты и задачи. Для условий используется Markdown, для начального кода — Monaco | [Форма работы](../src/AssignmentForm.jsx) |
| Список практических работ | Оформление как у банка задач и тестов: фильтр по предмету, поиск по названию, таблица. Преподаватель может создать работу, выбранный в фильтре предмет подставляется в форму | [Основные экраны](../src/main.jsx) |
| Банк задач и тестов | Общая таблица с фильтром по предмету и поиском. Кнопки «Обзор задачи» и «Обзор теста» открывают тот же преподавательский просмотр, что и в практической работе. Условия отдельных теоретических вопросов раскрываются в строке таблицы. У исходной работы сохраняются идентификатор и снимок задачи на момент прикрепления. При копировании курса новая работа хранит ссылку на задачу в общем банке и получает её содержимое при открытии. Копия предмета и её работы записываются вместе в `practice.library`. Теоретический вопрос хранит предмет и список идентификаторов связанных задач. Пустой список означает весь предмет | [Банк задач и тестов](../src/TaskBank.jsx) |
| Тема | `ThemeProvider` из Gravity UI применяет системную тему до первого ручного выбора. Кнопка «Настройки оформления» в шапке открывает выбор из трёх вариантов: «Системная», «Светлая» и «Тёмная». Системный режим учитывает изменения темы устройства. Выбор хранится в браузере, Monaco получает активную тему через `useThemeType` | [Управление темой](../src/Appearance.jsx) |
| Обзор и списки | `Card` для предмета, `Table` из UIKit для работ, `Label` для статуса. Сроки на обзоре показаны в столбце «Сдать до». На странице предмета кнопка «Все предметы» в шапке возвращает к списку | [Основные экраны](../src/main.jsx) |
| Обязательные поля | `FormRow required` из `@gravity-ui/components` показывает звёздочку. Свяжите `fieldId` с `id` поля и передайте `controlProps={{ required: true }}` в `TextInput` для проверки браузером | [Название предмета](../src/SubjectSettings.jsx) |
| Выбор групп, студентов и преподавателей | `Select` с `multiple` и `filterable`. Поиск по части имени или названия сохраняет выбор при смене запроса. Автор предмета сохраняет доступ | [Настройки доступа](../src/SubjectSettings.jsx) |
| Обложка | Две кнопки выбора одинаковой ширины, одна под другой. Каждая открывает `Popup` с `Palette` на 10 цветов или 10 иконок. У вариантов есть доступные названия. Предпросмотр и карточка используют один `SubjectCover` | [SubjectCover](../src/SubjectCover.jsx) |
| Группы на карточке преподавателя | `SubjectGroups` измеряет ширину строки. Подпись «ещё N» появляется при переполнении и учитывает место для самой подписи | [SubjectGroups](../src/SubjectGroups.jsx) |
| Документация и формулы | `MarkdownField` оборачивает редактор `@gravity-ui/markdown-editor`. Предпросмотр и чтение используют `MarkdownContent` с markdown-it и KaTeX. Исходный Markdown сохраняется для повторного редактирования | [Редактор](../src/MarkdownField.jsx) · [Отображение](../src/MarkdownContent.jsx) |

## Оформление и проверка

- Используйте встроенные состояния Gravity UI. Для основного действия подходит `Button view="action"`, для ведущей иконки — `Button.Icon`. Кнопки «Создать…» и «Добавить…» оформляйте текстом без иконки плюса. Акцент основного действия задаёт тема приложения. Цвет обложки выбирает преподаватель для конкретного предмета.
- Для каждого Markdown-поля используйте рамку со скруглением и подписью на верхней границе (`fieldset` и `legend`). Между соседними редакторами оставляйте отступ. Подпись должна быть видна и после ввода. Для пустого поля подберите вопрос или пример по смыслу, например «Что нужно проверить, прежде чем зачесть работу?».
- Для изменений доступа проверьте обе роли. Группы доступа и критерии приёма для преподавателя видны в его интерфейсе. В студенческом обзоре предметы, работы и сроки учитывают доступ и текущий семестр.
- Для изменений дат проверьте 31 января / 1 февраля и 31 августа / 1 сентября. Осенью на обзоре видны нечётные семестры, весной — чётные. В старых записях осени соответствует номер 1, весне — 2. Первая граница меняет сезон внутри учебного года, вторая начинает новый учебный год. В списке доступны текущий учебный год и три следующих. Открытие старого предмета сохраняет его прежний год.
